# Challenge 18 — Implement CTR mode

[← Previous](../challenge_17/) · [Next →](../challenge_19/) · [🇮🇹 Italiano](../../it/challenge_18/) · [Set 3 index](../../)

---

## Theory

CTR (Counter Mode) transforms a block cipher like AES into a stream cipher. Instead of encrypting the plaintext directly, CTR encrypts an incremental counter to generate a keystream, then XORs the keystream with the plaintext. The fundamental advantage is that CTR is parallelisable: each block can be encrypted independently, and decryption uses exactly the same operation as encryption.

The counter format in this implementation is: 8 bytes of nonce (a value used only once) followed by 8 bytes of counter in little-endian format. For the first block, the counter is 0; for the second, 1; and so on. This scheme is similar to the CTR format used in some real protocols.

A critical property of CTR: the keystream depends only on the key and nonce. If the same nonce is reused with the same key, the same keystream is obtained, and any modification to one message's ciphertext can be transferred to the other — exactly like a reused one-time pad. Challenges 19 and 20 exploit this weakness.

Compared to CBC, CTR requires no padding (partial blocks are handled using only the needed portion of the keystream), has no inter-block dependencies (parallelisable), and allows random access to the ciphertext.

## Key concepts

- **CTR mode:** stream cipher based on encrypting an incremental counter.
- **Keystream:** pseudorandom sequence generated by encrypting the counter; used for XOR with plaintext.
- **Nonce:** number used once; ensures different keystreams for different messages.
- **Little-endian counter:** the counter is serialised in 64-bit little-endian format.
- **`nonce_ctr_encrypt`:** CTR implementation with explicit nonce using `aessafe`.
- **`ssl_ctr_encrypt`/`ssl_ctr_decrypt`:** alternative OpenSSL-based implementation.

## Code walkthrough

### Overview

The `ssl_ctr_decrypt` method in `src/cryptovec/mod.rs` uses an incremental keystream. The `nonce_ctr_encrypt` method uses the `crypto` crate (`aessafe`) for a more explicit nonce-based implementation. The test uses `ssl_ctr_decrypt`.

### Implementation

`ssl_ctr_encrypt` (and its alias `ssl_ctr_decrypt`):

```rust
fn ssl_ctr_encrypt(&self, key: &[u8], pad: Option<bool>) -> Result<Vec<u8>, JlmCryptoErrors> {
    let mut ciphertext = Vec::new();
    let mut keystream = vec![0; 16];
    for b in self.chunks(16) {
        let to_xor = keystream.to_vec().ssl_ecb_encrypt(&key, pad);
        ciphertext.extend_from_slice(&b.to_vec().xor(to_xor.unwrap()));
        for b in keystream[16 / 2..].iter_mut() {
            *b += 1;
            if *b != 0 { break; }
        }
    }
    Ok(ciphertext)
}
```

The keystream starts all-zero. For each block: encrypt the keystream with ECB to get the keystream block, XOR with the plaintext/ciphertext block, increment the second half of the keystream as a counter.

`nonce_ctr_encrypt` with explicit nonce:

```rust
fn nonce_ctr_encrypt(&self, key: &[u8], nonce: Vec<u8>) -> Result<Vec<u8>, JlmCryptoErrors> {
    let block_size = key.len();
    let encryptor = aessafe::AesSafe128Encryptor::new(&key);
    let mut result: Vec<u8> = Vec::new();
    let mut keystream = vec![0; block_size];
    for (count, block) in self.chunks(block_size).enumerate() {
        let mut nonce_count = Vec::new();
        nonce_count.extend_from_slice(&nonce[..]);
        if let Ok(_) = nonce_count.write_u64::<LittleEndian>(count as u64) {
            encryptor.encrypt_block(&nonce_count[..], &mut keystream[..]);
            let b1 = &keystream[0..block.len()];
            let x_result = b1.to_vec().xor(block.to_vec());
            result.extend_from_slice(&x_result[..]);
        } else {
            return Err(JlmCryptoErrors::FailedAesCtrEncrypt);
        }
    }
    Ok(result)
}
```

For each block, construct `nonce || counter` in little-endian, encrypt it with AES, and XOR with the block. `write_u64::<LittleEndian>` from the `byteorder` crate serialises the counter.

### The test

```rust
#[test]
pub fn challenge_18() {
    let ciphertext = Base64::from_string(String::from(
        "L77na/nrFsKvynd6HzOoG7GHTLXsTVu9qvY/2syLXzhPweyyMTJULu/6/kXX0KSvoOLSFQ==",
    ));
    let cleartext = ciphertext.to_bytes().unwrap()
        .ssl_ctr_decrypt(b"YELLOW SUBMARINE", Some(true)).unwrap();
    let result = String::from_utf8_lossy(&cleartext);
    assert_eq!(result, "Yo, VIP Let's kick it Ice, Ice, baby Ice, Ice, baby ")
}
```

Decrypts the Base64 ciphertext with key "YELLOW SUBMARINE" in CTR mode and verifies the expected plaintext.
